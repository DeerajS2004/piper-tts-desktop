CURRENT BLOCKING ISSUE (NOT YET FIXED)
================================================================================

PROBLEM: App crashes with "Tcl_Release couldn't find reference / Aborted (core dumped)"

ROOT CAUSE: iconphoto() in Tkinter causes a C-level SIGABRT crash on this
  specific Tk/Linux build (Pop!_OS). This is a known Tcl/Tk bug.
  Python try/except CANNOT catch it — it's a C-level signal.

CURRENT STATE OF FIX (partially done):
  set_window_icon() now loads the PNG but does NOT call self.root.iconphoto()
  This was just applied — NOT YET TESTED by the user.

  If it works → the iconphoto fix was sufficient.

IF IT STILL CRASHES after removing iconphoto:
  The next suspect is tkfont.families() in update_text_widget_font()
  Fix: move it out of the function, cache it at class init level.
  Or simplify: just always use 'TkDefaultFont' which supports CJK.

  The function update_text_widget_font() calls tkfont.families() in a loop.

================================================================================
NOTES
================================================================================

- The app requires 'piper' binary in PATH. If installed via the venv, the
  launcher.sh activates the venv first. Running directly with python3 may fail
  at speech time if piper isn't in PATH. Activate the venv first:
    source ~/.local/share/piper-tts/venv/bin/activate
    python3 app/piper_gui.py

- Japanese Piper needs espeak-ng with Japanese data for phonemization.
  If Japanese speech fails, install: sudo apt install espeak-ng-data
  And check: espeak-ng --voices | grep ja

- The voice name changed: NOT "kenjirous" (doesn't exist), it's "hi_fi_captain"
  Correct URL pattern:
  https://huggingface.co/rhasspy/piper-voices/resolve/main/ja/ja_JP/hi_fi_captain/medium/ja_JP-hi_fi_captain-medium.onnx
